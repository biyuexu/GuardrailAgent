Executive Summary

Pre-Publication Status: NOT APPROVED — remediation required

Three Critical and five High findings were identified. Under the baseline's pre-publication gate, Critical findings require remediation before publication unless an explicitly authorized exception exists, and High findings require remediation or documented security approval.

The Admin Task Agent is a published, Teams-surfaced Copilot Studio agent that combines administrative write capability against Microsoft Entra ID, application-level Microsoft Graph read access, Office 365 mailbox management, a custom billing MCP server, SharePoint search, and three connected downstream agents — one of which ingests content from a public internet site and another of which runs autonomously on file upload and sends email without human review.

The agent does several things well: authentication is Integrated with an authentication trigger of Always, content moderation is set to High, useModelKnowledge is disabled, ownership is clearly attributable, and the SharePoint project-search flow correctly uses invoker identity so results are trimmed to the signed-in user's permissions. These are genuine strengths and they meaningfully limit several attack paths.

Most urgent issue: a plaintext Microsoft Graph application client secret is stored directly in the definition of the “get assigned licenses” Power Automate flow (workflow 4b67d3a5-7469-f011-bec1-7c1e520b6058). This credential is exploitable without interacting with the agent at all, is not bound to any user session, and survives every other remediation. It should be rotated first. The secret value is deliberately not reproduced in this report.

The dominant structural weakness is that untrusted, externally-authored content and privileged, state-changing tools share a single reasoning context with no enforced authorization boundary between them. GenerativeActionsEnabled is true, the Entra group-membership parameter is an AutomaticTaskInput supplied by the model with no confirmation, and four connections execute under the maker (a tenant administrator) rather than the invoking user. Individually these are control failures; together they form the chained attack paths set out in this report.

Critical & High Findings

SEC-001 / DATA-006
Secrets Must Not Exist in Instructions / Embedded in Agent Content
FAIL Critical
Observed Evidence

Flow 'get assigned licenses' (workflowid 4b67d3a5-7469-f011-bec1-7c1e520b6058), action 'HTTP', contains an inline ActiveDirectoryOAuth block with authority tenant 1a2d00d3-eb2f-45c4-9a7f-7c8303e8401c, clientId d3abaf28-0cbf-48a9-a4e1-154bf77ab9dd, audience https://graph.microsoft.com, and a plaintext 40-character client secret literal beginning '_Bi8Q~' stored directly in the workflow clientdata. The flow is Activated (statecode 1 / statuscode 2 Activated).

Expected State

Credentials must never be stored in agent instructions, topics, knowledge, or flow definitions. Authentication must use an approved credential-management mechanism (managed identity, Key Vault reference, or a connection reference) per SEC-003 and SEC-004.

Analysis

The secret is readable by anyone who can read the workflow definition in this environment - which includes every maker with access to the Default solution, anyone who can export the unmanaged solution, and any identity with Dataverse read on the workflow table. Because the credential is an application (app-only) Microsoft Graph credential, it is not bound to the invoking user and does not expire with a session.

Risk

Full compromise of the registered application's Microsoft Graph permissions, independent of the agent. An attacker holding this secret can call Graph directly outside all Copilot Studio controls, with no attribution to an end user. This is a standing tenant-level credential exposure, not merely an agent weakness.

Recommendation

1) Treat the secret as compromised and rotate/revoke it immediately on app registration d3abaf28-0cbf-48a9-a4e1-154bf77ab9dd. 2) Remove the inline 'authentication' block from the HTTP action. 3) Replace with a Key Vault reference or an Entra ID connection reference, or replace the raw HTTP call with the shared_azuread / shared_office365users connector already present in the environment. 4) Review Graph sign-in and audit logs for that appId for use from unexpected IPs since 2026-09-17. 5) Review the app registration's granted Graph application permissions and reduce to User.Read.All or narrower.

Validation

Re-export the flow definition and confirm no literal secret string remains in clientdata; confirm the old secret no longer authenticates against Graph; re-run SEC-001, SEC-003, SEC-004 and DATA-006.

IAM-004 / DATA-003
Privileged Access Requires Justification / Cross-User Data Access Must Be Authorized
FAIL High
Observed Evidence

The same flow calls Graph with an application identity, not the delegated user. The URI is /v1.0/users/@{triggerBody()?['text']}?$select=assignedLicenses. The 'text' input is declared as a ManualTaskInput defaulted to =System.User.PrincipalName, but it is a free-form string parameter on a Skills-kind Request trigger, not a server-enforced binding.

Expected State

License lookups for a self-service agent should execute under the invoking user's delegated context, or the parameter must be enforced server-side to the caller's UPN so one user cannot query another user's record.

Analysis

App-only Graph authorization ignores the caller's own permissions. The conversation starter 'what are the licenses assigned to me?' reflects self-service intent, but the technical configuration permits lookup of any UPN in the tenant. The restriction to 'me' exists only as a default value and as natural-language instruction text, which INST-001 explicitly prohibits as a sole authorization boundary.

Risk

Any user who can reach the agent can potentially enumerate license assignment - and therefore product entitlement, role and staffing signal - for arbitrary employees. Combined with the email capability this becomes a directory-reconnaissance and exfiltration primitive.

Recommendation

Switch the flow to a delegated Entra ID / Office 365 Users connection so Graph enforces the caller's rights, or hard-bind the UPN server-side inside the flow (ignore the trigger input and resolve the caller identity in the flow itself). Remove the free-form 'text' parameter from the trigger schema.

Validation

Attempt a license lookup for a UPN other than the signed-in user and confirm it is denied; re-run IAM-004, IAM-009 and DATA-003.

IAM-005 / HUMAN-001 / HUMAN-002
High-Impact Actions Require Authorization / Human Oversight
FAIL High
Observed Evidence

Action 'add user to security group' (copilot_adobeAgent.action.addusertosecuritygroup) invokes flow 0909de90-3472-f011-b4cb-7c1e520b6058, which performs shared_azuread AddUserToGroup. The group is a ManualTaskInput pinned to 42d2fdd2-f3de-4988-b61e-d40e578b8bc2, but the member 'email' is declared kind: AutomaticTaskInput - i.e. the model supplies it without user confirmation. The topic contains no confirmation prompt, no approval node, and no allow-list. A conversation starter ships this capability to every user: 'add admin@M365CPI06134360.onmicrosoft.com to the security group'.

Expected State

Modification of Entra ID group membership is a security-control change. Per IAM-005, IAM-010 and HUMAN-002 it requires an authorization mechanism enforced outside the model, and approval must occur before the action.

Analysis

Entra security groups commonly gate application access, Conditional Access policy, licensing, SharePoint permissions and - relevant here - Copilot Studio agent access itself, since every agent in this environment uses accesscontrolpolicy 'Group membership'. Because the parameter is an AutomaticTaskInput, any text that reaches the model's context and is interpreted as an instruction can determine who is added. GenerativeActionsEnabled is true, so the orchestrator may select this tool without an explicit deterministic topic trigger.

Risk

Unauthorized privilege escalation. An attacker who can influence the model's context can add an account they control to a privileged group, gaining whatever access that group confers, with the change attributed to the maker's embedded connection rather than to the attacker.

Recommendation

1) Remove this action from the agent unless group administration is a confirmed requirement. 2) If retained: change 'email' from AutomaticTaskInput to an explicit user-confirmed input; add an explicit confirmation/approval step before the AddUserToGroup call; restrict the flow to an allow-list of permitted target groups and permitted requestors; and switch the azuread connection from embedded to invoker so the change is authorized by the requesting user's own Entra rights. 3) Enable Entra ID group-membership change auditing and alerting for group 42d2fdd2-f3de-4988-b61e-d40e578b8bc2.

Validation

Attempt the action as a non-privileged user and confirm it is blocked or requires explicit approval; confirm the Entra audit log attributes the change to a named requestor; re-run IAM-005, IAM-010, HUMAN-001 and HUMAN-002.

ATT-001 / PI-002 / PI-004
High-Risk Capability Combinations - Untrusted Content plus Privileged Tools
FAIL Critical
Observed Evidence

The agent simultaneously (a) ingests untrusted external content - Trimble Spectrum connected agent whose knowledge source is the public site https://help.trimble.com/en/spectrum plus a URL-fetch action, Microsoft Learn Docs MCP, SharePoint search results, and isFileAnalysisEnabled: true; and (b) holds privileged capability - Entra ID group write, app-only Graph read, and Office 365 mailbox management in Maker mode. GenerativeActionsEnabled is true and all three connected agents receive historyType: ConversationHistory. No content-trust separation is configured.

Expected State

Per PI-002 and PI-004, retrieved content must not be able to authorize privileged tool calls, and external content must not outrank trusted instructions. Per ATT-001, the combination must be evaluated as a single risk, not as separate controls.

Analysis

This is the canonical indirect prompt injection chain: attacker-controlled content -> retrieval -> context injection -> agent reasoning -> tool invocation. The injected text does not need to come from the user; a poisoned page, a poisoned SharePoint document in the searched library, or a crafted file uploaded for analysis is sufficient. Content moderation is set to High, which filters harmful content but is not an injection control and does not constrain tool authorization.

Risk

A single piece of attacker-authored content could cause the agent to add an attacker-controlled account to the Entra security group, read or forward mailbox content via the Email Management MCP, and enumerate directory license data - all executing under the maker's privileged connections.

Recommendation

Break the chain rather than hardening one link: (1) remove the Entra group-write action from an agent that also ingests external content, or isolate it into a separate, tightly-scoped agent with no external knowledge; (2) require explicit human approval before any group change or outbound email; (3) move Maker-mode connections to invoker/user authentication so injected instructions cannot exceed the invoking user's own rights; (4) constrain the Trimble URL-fetch action to an allow-list of help.trimble.com paths.

Validation

Conduct an injection test: place benign marker instructions in a document in the searched SharePoint library and in a file submitted for analysis, then confirm the agent does not invoke the group-add or email tools as a result. Re-run PI-002, PI-003, PI-004 and ATT-001.

ATT-001 / PI-002 / EXT-001
Autonomous Trigger plus Untrusted File plus Outbound Email (via HR Agent)
FAIL Critical
Observed Evidence

Connected agent HR Recruiting Agent (copilot_hrAgent) has an External Trigger component 'When a file is created' bound to OneDrive for Business (flow 134b8eda-e277-f011-b4cb-7c1e520b6058). Its instructions direct it to read the uploaded resume, judge the candidate, and then 'Compose and Send an Email' using Office 365 Outlook Send an email (V2). That connector runs with connectionProperties mode: Maker. The email body is entirely model-generated from the uploaded file's content.

Expected State

Per PI-002, retrieved content must not independently authorize external communications; per HUMAN-002, approval must precede the consequential action. An autonomous agent that processes untrusted files and then emails must have an authorization gate between ingestion and transmission.

Analysis

The file is uploaded by a third party (a candidate) and is therefore fully attacker-controlled. The trigger fires without any human in the loop, and the outbound send occurs in the same uninterrupted turn. Mitigating factor: the 'To' address is a ManualTaskInput fixed to admin@M365CPI06134360.onmicrosoft.com, so the recipient cannot be freely redirected by the model - this materially limits, but does not eliminate, the exposure, because the body is unconstrained and the agent also holds a SharePoint knowledge source over https://m365cpi06134360.sharepoint.com/Shared%20Documents.

Risk

A crafted resume can drive the content of an automatically-sent email from the maker's mailbox and can attempt to steer the agent into surfacing content from the SharePoint document library into that message. Because the Admin Task Agent invokes this agent with full ConversationHistory, injected instructions can also propagate back toward the parent's privileged tools.

Recommendation

1) Insert a human approval step between candidate analysis and email send, so a reviewer sees the draft before transmission (HUMAN-002/HUMAN-003). 2) Keep the fixed recipient and additionally constrain the email body to a fixed template with bounded fields rather than free model output. 3) Switch the Outlook connection from Maker to invoker, or to a dedicated service identity with send-only scope. 4) Narrow the SharePoint knowledge source from the root /Shared%20Documents library to a dedicated recruiting folder.

Validation

Upload a test file containing benign marker instructions, confirm no email is sent without approval and that the marker text does not appear in any output; re-run PI-002, EXT-001, HUMAN-001 and HUMAN-002.

IAM-007 / SEC-004
Shared Privileged Identities Must Be Restricted / Credential Scope Must Be Limited
FAIL High
Observed Evidence

Four connections execute under the maker rather than the end user: Office 365 Outlook Email Management MCP (mode: Maker), billing MCP (mode: Maker), Microsoft Learn Docs MCP (mode: Maker), and - downstream - the HR Agent's Send an email V2 (mode: Maker). The 'add user to security group' flow likewise uses runtimeSource: 'embedded' for both shared_azuread and shared_office365users. The agent owner and creator is MOD Administrator (0a7449d3-6b8c-f111-ab0e-6045bd09cc66).

Expected State

Privileged agent operations should run under an attributable application/service identity or an appropriately scoped delegated identity, not a shared maker account (IAM-007), and credentials should carry only the permissions the integration requires (SEC-004).

Analysis

This is a confused-deputy configuration. Every user of the agent inherits the maker's effective rights for these operations. Because the maker is a tenant administrator account, the blast radius is the administrator's entire mailbox and directory authority. It also defeats attribution: MON-002 requires determining which identity executed an action, but the connector logs will show the maker for every invocation regardless of who asked.

Risk

Privilege escalation for every agent user, and loss of per-user accountability for mailbox access, license enumeration and group changes.

Recommendation

Change the Office 365 Outlook, billing MCP and Microsoft Learn connections to end-user (invoker) authentication. Where a service identity is genuinely required, create a dedicated, non-administrative service principal scoped only to the needed operations, and re-own the agent to that purpose-built identity rather than the tenant administrator account.

Validation

Re-inspect each action's connectionProperties and confirm mode is no longer Maker; confirm an end user cannot reach mailbox content they do not own; re-run IAM-007, IAM-009, SEC-004 and MON-002.

IAM-006 / DEF-001
Broad User Access Must Be Justified / Secure Defaults
WARNING High
Observed Evidence

The bot record sets accesscontrolpolicy = 2 ('Group membership'), but the authorizedsecuritygroupids attribute returns no value. The agent is published (publishedon 2026-09-17 22:32:58), Active/Provisioned, has a Teams application manifest (v1.0.0), and authenticationmode is Integrated with authenticationtrigger Always.

Expected State

An agent holding Entra ID write, app-only Graph read and mailbox management must have its audience explicitly restricted to a named, justified security group, and the restrictive option must be the configured default.

Analysis

Integrated authentication with 'Always' trigger is a genuine strength - every user is authenticated before the agent responds, and the agent is not anonymously reachable. However, an access policy of 'Group membership' with no group IDs recorded is an internally inconsistent state: the intended restriction is declared but the scoping evidence is absent. Risk

If no group is in fact bound, the population able to invoke Entra group modification and mailbox tooling is far wider than the agent's administrative purpose warrants, which is exactly the 'Broad users + administrative permissions' combination ATT-001 requires to be escalated.

Recommendation

Confirm in Copilot Studio (Settings > Security > Authentication / Sharing) which security groups are bound. If none, bind a named administrator group now and populate authorizedsecuritygroupids before publication. Document the justification for the chosen audience.

Validation

Re-query the bot record and confirm authorizedsecuritygroupids is populated; verify a user outside that group cannot invoke the agent; re-run IAM-006 and DEF-001.

TOOL-005 / KNOW-002
External Tools Must Have Established Trust
FAIL High
Observed Evidence

The 'billing MCP' action targets custom connector af300692-6839-49af-b4b0-f58c76e8267c (shared_copilot-5fbilling-20mcp-5f7af054f600195485) with operationId InvokeServer and triggerCondition: true. A2A-004 / A2A-003
Sensitive Data Passed Between Agents Must Be Controlled
WARNING Medium
Observed Evidence

All three connected agents - HR Agent, SPO site metadata M365 Agent and Trimble Spectrum - are invoked with historyType: ConversationHistory, meaning the full conversation is passed downstream. The SPO agent (copilot_spoAgent, 'Site metadata and Dataverse M365 Agent') has authenticationtrigger 'As Needed' (0), weaker than the parent's 'Always' (1).

Expected State

Data exchanged between agents must respect the originating user's and agent's authorization boundaries, and chaining must not create unauthorized privilege escalation (A2A-003, A2A-004).

Passing full conversation history to three separate agents - including one that reaches a public external website and one that performs employment screening - widens the disclosure surface beyond what each downstream agent needs. Recommendation

Switch downstream invocations from ConversationHistory to a scoped input contract that passes only the parameters each agent needs. Align the SPO agent's authenticationtrigger to 'Always'. Obtain and document the SPO agent's tool and permission inventory before publication.

Validation

Confirm each connected agent receives only scoped inputs; confirm the SPO agent's authenticationtrigger is 'Always'; re-run A2A-002, A2A-003 and A2A-004.

TOOL-004
Tool Parameters Must Be Constrained
FAIL Medium
Observed Evidence

Flow 'search project details' (0c5fb740-af73-f011-b4cb-7c1e520b6058) interpolates a model-extracted string directly into a SharePoint search URL: _api/search/query?querytext='@{triggerBody()?['text']}'&$top=3 against https://m365cpi06134360.sharepoint.com. The action's description instructs the model to 'extract the searchString that can be queried against a sharepoint online list'. No validation, escaping or allow-list is present.

Expected State

User-controlled or externally sourced values must not freely determine tool parameters without validation.

Analysis

An unescaped value inside a KQL querytext parameter permits query manipulation - for example breaking out of the intended scope with additional KQL operators or appending further query-string parameters. Significant mitigating factor: this connection uses runtimeSource 'invoker', so SharePoint search trims results to what the signed-in user is already permitted to see. That caps this at query manipulation within the user's own entitlement rather than cross-user disclosure, which is why severity is Medium rather than High.

Risk
